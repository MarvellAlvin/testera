BAGIAN 2 — FORMAT ANGKA OTOMATIS (R14, NEW)
--------------------------------------------------------------------------------

2.1 ATURAN UMUM:
     - SEMUA input nominal (transaksi, budget, goal, deposit, harga aset,
       DCA, simulator, dsb.) memakai AmountTextField custom.
     - SEMUA tampilan nominal memakai formatter.formatIdr(value) ->
       "Rp1.000.000".
     - User mengetik digit -> langsung tampil dengan titik ribuan.
       Placeholder "0".
     - Hapus digit -> reformat seketika.
     - Kursor tetap di kanan digit yang relevan (best-effort; kalau
       perlu, pakai offset mapping naif).
     - TIDAK BOLEH ada field nominal yang menampilkan angka mentah
       (mis. 1000000) di UI.
     - DB menyimpan Long (untuk IDR) atau String berisi BigDecimal
       (untuk kuantitas pecahan). TIDAK PERNAH string berformat.

2.2 CONTOH WAJIB (UJI R14):
     Input user   | Tampil di field | Disimpan DB
     -------------|-----------------|-------------
     "100"        | "100"           | 100L
     "1000"       | "1.000"         | 1000L
     "10000"      | "10.000"        | 10000L
     "100000"     | "100.000"       | 100000L
     "1000000"    | "1.000.000"     | 1000000L
     "10000000"   | "10.000.000"    | 10000000L

2.3 IMPLEMENTASI:
     - Gunakan TextFieldValue + VisualTransformation custom
       "ThousandsSeparatorTransformation".
     - Alternatif: onValueChange strip non-digit -> formatIdr ->
       set text.
     - JANGAN memakai library eksternal (mis. Compose Money).
     - JANGAN memakai Double untuk parsing. Pakai Long.parseLong untuk
       IDR.
     - Locale: IDR pakai "." ribuan; USD pakai "," ribuan + "."
       desimal. Semua via NumberFormat.getNumberInstance(locale).

2.4 KUANTITAS PECAHAN (INVESTASI):
     - Emas (gram):
         maks 3 desimal.
         Ketik "0,001" -> simpan BigDecimal("0.001").
         Tampil "0,001 g".
         Separator desimal: koma (locale Indonesia).
         Pengguna boleh ketik "0.001" atau "0,001" -> keduanya OK.
     - Crypto (coin):
         maks 4 desimal.
         "0,0001" -> BigDecimal("0.0001").
         Tampil "0,0001 BTC".
     - Saham IDX / Saham AS (lot):
         integer.
         1 lot IDX = 100 lembar.
         Input "5" -> berarti 5 lot (bukan 5 lembar).
     - ETF (shares):
         integer.
     - Reksa Dana (Rp):
         integer rupiah.
     - Deposito (Rp):
         integer rupiah + persen (2 desimal) + durasi (integer hari).

2.5 BUKTI R14:
     - Screenshot 5 angka pada form transaksi (100, 1.000, ..., 1.000.000).
     - Unit test ThousandsSeparatorTransformationTest:
         5 kasus + edge (0, 000, leading zeros "007", "1.000.000" -> parse
         balik ke 1000000L, hapus digit di tengah).
     - Screenshot emas "0,001" & crypto "0,0001" tanpa kehilangan presisi.
     - Screenshot DB (via Android Studio Database Inspector):
         kolom amount = 1000000 (Long), bukan "1.000.000".

2.6 EDGE CASE WAJIB:
     - Input kosong -> tampil "0" placeholder, tidak error.
     - Input "0" -> tetap "0" (bukan "000").
     - Input "0001" -> otomatis jadi "1" (leading zeros dibuang saat
       parse).
     - Input "-" -> diabaikan (tidak boleh minus di field nominal).
     - Input "," -> untuk IDR diabaikan; untuk kuantitas investasi
       diizinkan sekali.
     - Copy-paste "Rp1.500.000" -> di-strip jadi "1500000" -> tampil
       "1.500.000".
     - Copy-paste "1,000,000" (locale US) -> di-strip jadi "1000000"
       -> tampil "1.000.000".
     - Semua ini WAJIB ada unit test.

5.5 CARA HITUNG (WAJIB BIGDECIMAL):

     COST BASIS:
       sumBuy = Σ (BUY.quantity x BUY.pricePerUnit) + Σ (BUY.fee)
       sumSell = Σ (SELL.quantity x SELL.pricePerUnit) - Σ (SELL.fee)
       costBasis = sumBuy - sumSell

     NILAI SEKARANG:
       currentValue = currentQuantity x currentPrice

     GAIN/LOSS:
       unrealized = currentValue - costBasis
       realized = Σ (SELL.quantity x (SELL.pricePerUnit - avgBuyAtSell))
       totalGainLoss = unrealized + realized

     TOTAL KEKAYAAN (net):
       totalWealth = Σ saldo akun (Q1)
                     + Σ currentValue (semua aset investasi)
                     + Σ realized (dari tx SELL)

     CONTOH USER (wajib benar):
       User catat investasi 1.000.000
       Nilai sekarang 500.000
       Maka yang masuk Total Kekayaan = +500.000 (bukan 1.000.000).

     PEMBULATAN:
       Semua BigDecimal.setScale(2, RoundingMode.HALF_UP) untuk rupiah.
       Simpan internal dengan presisi penuh; tampilkan dengan skala 2.

5.7 DEPOSITO — AUTO-UPDATE (WAJIB):

     FORM DEPOSITO:
       - Pokok (Rp).
       - Bunga per tahun (%) — BigDecimal, mis. 5,50.
       - Tenor (hari) — integer >= 1, mis. 14.
       - Tanggal mulai — date picker (default hari ini).
       - Auto-renew? — Switch "Ya, perpanjang otomatis saat jatuh tempo".

     PERHITUNGAN:
       bungaPeriode = pokok x (rate/100) x (tenor/365)
                      (basis hari kalender)
                      RoundingMode.HALF_UP, 2 desimal.
       nilaiJatuhTempo = pokok + bungaPeriode.
       tanggalJatuhTempo = startDate + tenor hari.

     ENGINE AUTO-UPDATE:
       - DepositAutoRenewWorker / deferred check di AppInitializer.
       - Saat app dibuka (deferred, sekali per proses, idempoten):
           Untuk setiap deposito autoRenew=true dengan dueDate <= today:
             - Buat InvestmentTx(kind=RENEW) dengan nilai baru =
               nilaiJatuhTempo.
             - Update asset.quantity = nilaiJatuhTempo.
             - Update asset.depositStartDate = dueDate (tanggal jatuh
               tempo sebelumnya).
             - Update asset.updatedAt = now.
       - IDEMPOTENCY KEY:
           id = "dep-{assetId}-{dueDateISO}"
           Sebelum insert, cek apakah InvestmentTx dengan id tersebut
           sudah ada. Jika ada, skip (bukti M12).
       - SUMBER TANGGAL:
           System.currentTimeMillis() -> format ISO lokal (baca dari HP).
       - DILARANG pakai WorkManager periodik < 15 menit atau
         AlarmManager jangka pendek (R-D8).
       - Loop: sementara dueDate <= today, terus update (jika tenor
         pendek, misal 14 hari dan app tidak dibuka 30 hari, harus
         update 2x).

     CONTOH:
       Deposito 10.000.000, 5,50%, 14 hari, mulai 2025-01-01.
       Jatuh tempo: 2025-01-15.
       Bunga: 10.000.000 x 0.055 x (14/365) = 21.095,89.
       Nilai baru: 10.021.095,89.
       Bila auto-renew: depositStartDate jadi 2025-01-15, jatuh tempo
       berikutnya 2025-01-29.

     - Keyword challenge: fetch kategori+periode dulu (kecil, via indeks)
       lalu LIKE di Kotlin.

8.2 QUERY WAJIB (DAO; sesuaikan nama kolom, jangan ubah semantik):

     Q1 saldo akun (1 query):
       SELECT a.id, a.name, a.icon, a.openingBalance,
         a.openingBalance
         + COALESCE(SUM(CASE WHEN t.type='income'   AND t.accountId   = a.id THEN t.amount ELSE 0 END),0)
         + COALESCE(SUM(CASE WHEN t.type='transfer' AND t.toAccountId = a.id THEN t.amount ELSE 0 END),0)
         - COALESCE(SUM(CASE WHEN t.type='expense'  AND t.accountId   = a.id THEN t.amount ELSE 0 END),0)
         - COALESCE(SUM(CASE WHEN t.type='transfer' AND t.accountId   = a.id THEN t.amount ELSE 0 END),0)
         AS balance
       FROM accounts a LEFT JOIN transactions t
         ON (t.accountId = a.id OR t.toAccountId = a.id)
       GROUP BY a.id

     Q2 ringkasan rentang:
       SELECT type, SUM(amount)
       FROM transactions
       WHERE date BETWEEN :from AND :to AND type != 'transfer'
       GROUP BY type

     Q3 top kategori:
       SELECT c.id, c.name, c.icon, SUM(t.amount) total
       FROM transactions t JOIN categories c ON c.id = t.categoryId
       WHERE t.date BETWEEN :from AND :to AND t.type = 'expense'
       GROUP BY c.id
       ORDER BY total DESC
       LIMIT 6

     Q4 bucket cashflow:
       SELECT date,
         SUM(CASE WHEN type='income'  THEN amount ELSE 0 END) income,
         SUM(CASE WHEN type='expense' THEN amount ELSE 0 END) expense
       FROM transactions
       WHERE date BETWEEN :from AND :to AND type != 'transfer'
       GROUP BY date
       ORDER BY date
       (rentang > 31 hari: GROUP BY substr(date,1,7))

     Q5 recent 8:
       SELECT rowid, t.id, t.type, t.note, t.date, t.amount,
              t.accountId, t.toAccountId, c.icon catIcon
       FROM transactions t
       LEFT JOIN categories c ON c.id = t.categoryId
       ORDER BY t.date DESC, rowid DESC
       LIMIT 8

     Q6 keyset pagination:
       (halaman pertama: lastDate='9999-12-31',
        lastRowid=9223372036854775807)
       SELECT rowid, *
       FROM transactions
       WHERE (:q IS NULL OR note LIKE '%' || :q || '%')
         AND (:type IS NULL OR type = :type)
         AND (:cat IS NULL OR categoryId = :cat)
         AND (:acc IS NULL OR accountId = :acc)
         AND (date < :lastDate OR (date = :lastDate AND rowid < :lastRowid))
       ORDER BY date DESC, rowid DESC
       LIMIT 50

     Q7 count terfilter (footer):
       SELECT COUNT(*)
       FROM transactions
       WHERE (:q IS NULL OR note LIKE '%' || :q || '%')
         AND (:type IS NULL OR type = :type)
         AND (:cat IS NULL OR categoryId = :cat)
         AND (:acc IS NULL OR accountId = :acc)

     Q8 budget:
       SELECT SUM(amount)
       FROM transactions
       WHERE type = 'expense'
         AND categoryId = :cat
         AND date >= :cycleStart
         AND date <  :cycleEnd

     Q9 baseline ReducePercent:
       SELECT COALESCE(SUM(amount),0) / 30.0 AS avgDaily
       FROM transactions
       WHERE type = 'expense'
         AND categoryId = :cat
         AND date <  :start
         AND date >= :startMinus30

     Q10 total investasi per jenis:
       SELECT type,
              SUM(CAST(quantity AS REAL) * CAST(currentPrice AS REAL))
       FROM investment_assets
       GROUP BY type
       -- dikembalikan sebagai pasangan (String, String)
       -- dan dikonversi ke BigDecimal di VM.

     Q11 gain/loss total:
       -- dihitung di Kotlin dari hasil Q10 + cost basis (BigDecimal, VM)
       -- BUKAN SQL float.

     Q12 riwayat investasi keyset:
       SELECT *
       FROM investment_tx
       WHERE (:type IS NULL OR :type = kind)
         AND (date < :lastDate OR (date = :lastDate AND rowid < :lastRowid))
       ORDER BY date DESC, rowid DESC
       LIMIT 50

     Q13 deposito jatuh tempo:
       SELECT *
       FROM investment_assets
       WHERE type = 'DEPOSITO'
         AND depositAutoRenew = 1
         AND date(depositStartDate, '+' || depositTenorDays || ' days') <= :today

CATATAN ADAPTASI WEB -> ANDROID (R17)
--------------------------------------------------------------------------------

Semua permintaan berbasis web di daftar user dipetakan ke padanan
native:

  IndexedDB / Dexie.js       ->  Room (SQLite)
  Zustand / Jotai            ->  ViewModel + StateFlow
  PWA (installable)          ->  APK / AAB installable
  Service Worker (offline)   ->  WorkManager + Room (source of truth)
  Code Splitting             ->  R8 + dynamic feature modules
  Multi-Platform Sync        ->  (tidak ada; STUB, butuh backend)
  Web Worker                 ->  Dispatchers.Default/IO
  LocalStorage               ->  DataStore Preferences
  Session Storage            ->  ViewModel (in-memory, non-persistent)

Fitur yang butuh data live dari internet TIDAK dapat diimplementasikan
secara jujur tanpa API berbayar:
  - Harga saham / crypto realtime (butuh API seperti Yahoo Finance,
    Alpha Vantage, CoinGecko Pro).
  - Kurs otomatis (butuh API forex).
  - Dividend auto-fetch (butuh API khusus).
  - Sync cloud / multi-device (butuh backend).
  - Two-way calendar sync (butuh akun Google).

Fitur-fitur di atas ditandai STUB/TODO dengan penjelasan API mana
yang dibutuhkan bila kelak user ingin menambahkannya.
